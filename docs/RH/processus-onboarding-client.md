# PROCESSUS D'ONBOARDING CLIENT - GENIUS WORK

## APERÇU DU PROCESSUS

Le processus d'onboarding client de Genius Work est conçu pour assurer une transition fluide depuis la signature du contrat jusqu'à l'autonomie complète du client. Ce processus est structuré en 5 phases principales, avec des responsabilités clairement définies pour chaque membre de l'équipe.

**Durée totale estimée** : 4 à 6 semaines selon la taille et la complexité de l'entreprise cliente

## PHASE 1 : PRÉ-ONBOARDING (SEMAINE 1)

### Objectifs
- Finaliser les aspects administratifs et contractuels
- Collecter les informations nécessaires à la configuration
- Préparer le plan d'implémentation personnalisé

### Étapes et responsabilités

#### Jour 1-2 : Finalisation administrative
- **Roxane (COO)**
  - Finaliser et signer le contrat de service
  - Collecter les documents administratifs (RCCM, attestation fiscale, etc.)
  - Créer le dossier client dans le système de gestion documentaire
  - Émettre la facture initiale selon les conditions du contrat

#### Jour 3-4 : Collecte d'informations
- **Fidel (Business Dev)**
  - Organiser une réunion de kickoff avec le client
  - Présenter l'équipe projet côté Genius Work
  - Identifier les interlocuteurs clés côté client (sponsor, admin, référents techniques)
  - Remplir le questionnaire de configuration avec le client

- **M'Bene (Support Client)**
  - Créer le compte client dans le système de ticketing
  - Envoyer les accès au portail client
  - Préparer le document de spécifications client

#### Jour 5 : Planification
- **Fidel (Business Dev) & M'Bene (Support Client)**
  - Élaborer le plan d'implémentation personnalisé
  - Définir le calendrier des formations
  - Identifier les risques potentiels et les mesures d'atténuation
  - Présenter et valider le plan avec le client

### Livrables
- Contrat signé et archivé
- Dossier client complet
- Questionnaire de configuration rempli
- Plan d'implémentation validé
- Calendrier des formations

## PHASE 2 : CONFIGURATION TECHNIQUE (SEMAINE 2)

### Objectifs
- Créer et configurer le tenant du client dans le système
- Mettre en place l'infrastructure technique nécessaire
- Configurer les paramètres spécifiques au client

### Étapes et responsabilités

#### Jour 1-2 : Création de l'environnement
- **Jérémie (CEO/CTO)**
  - Créer le tenant client dans l'architecture multi-tenant
  - Configurer les paramètres de sécurité et d'isolation des données
  - Mettre en place les accès API si nécessaire
  - Vérifier l'intégrité de l'environnement

#### Jour 3-4 : Configuration de base
- **M'Bene (Support Client)**
  - Configurer les paramètres de base de l'entreprise (nom, logo, fuseaux horaires)
  - Créer le compte administrateur principal
  - Configurer les méthodes de pointage sélectionnées par le client
  - Paramétrer les notifications et alertes

#### Jour 5 : Configuration avancée
- **M'Bene (Support Client) & Jérémie (CEO/CTO)**
  - Configurer les règles de calcul spécifiques (retards, heures supplémentaires)
  - Mettre en place les intégrations avec les systèmes tiers si nécessaire
  - Effectuer les tests de configuration
  - Préparer l'environnement pour l'import des données

### Livrables
- Tenant client créé et configuré
- Compte administrateur principal opérationnel
- Méthodes de pointage configurées
- Rapport de tests de configuration
- Documentation technique spécifique au client

## PHASE 3 : IMPORT DES DONNÉES ET STRUCTURATION (SEMAINE 3)

### Objectifs
- Importer et structurer les données de l'entreprise
- Configurer l'organigramme et les hiérarchies
- Préparer l'environnement pour les utilisateurs

### Étapes et responsabilités

#### Jour 1-2 : Préparation des données
- **M'Bene (Support Client)**
  - Fournir les modèles d'import au client
  - Accompagner le client dans la préparation des fichiers d'import
  - Valider la qualité et la conformité des données

#### Jour 3-4 : Import et structuration
- **M'Bene (Support Client) & Jérémie (CEO/CTO)**
  - Importer les données des employés
  - Configurer les départements et services
  - Structurer l'organigramme et les relations hiérarchiques
  - Configurer les sites et zones géographiques
  - Paramétrer les horaires de travail et planning

#### Jour 5 : Validation des données
- **M'Bene (Support Client) & Client**
  - Vérifier l'intégrité des données importées
  - Corriger les éventuelles anomalies
  - Valider la structure organisationnelle avec le client
  - Effectuer des tests avec des données réelles

### Livrables
- Données employés importées et validées
- Structure organisationnelle configurée
- Sites et zones géographiques paramétrés
- Horaires et plannings configurés
- Rapport de validation des données

## PHASE 4 : FORMATION ET TESTS (SEMAINE 4)

### Objectifs
- Former les différents profils d'utilisateurs
- Effectuer des tests en conditions réelles
- Préparer le déploiement

### Étapes et responsabilités

#### Jour 1-2 : Formation des administrateurs
- **M'Bene (Support Client)**
  - Former les administrateurs système
  - Former les responsables RH
  - Former les gestionnaires de planning
  - Remettre la documentation administrateur

#### Jour 3 : Formation des managers
- **M'Bene (Support Client)**
  - Former les managers sur leurs fonctionnalités spécifiques
  - Expliquer le processus de validation des présences et congés
  - Former à l'utilisation des tableaux de bord et rapports
  - Remettre la documentation manager

#### Jour 4 : Tests pilotes
- **M'Bene (Support Client) & Fidel (Business Dev)**
  - Sélectionner un groupe pilote d'employés
  - Effectuer des tests de pointage en conditions réelles
  - Tester les différentes méthodes de pointage configurées
  - Recueillir les retours et ajuster si nécessaire

#### Jour 5 : Préparation au déploiement
- **Équipe complète & Client**
  - Présenter les résultats des tests pilotes
  - Valider le plan de déploiement
  - Finaliser le matériel de formation des employés
  - Préparer la communication interne

### Livrables
- Administrateurs et managers formés
- Documentation utilisateur remise
- Rapport des tests pilotes
- Plan de déploiement validé
- Matériel de formation des employés

## PHASE 5 : DÉPLOIEMENT ET SUIVI (SEMAINE 5-6)

### Objectifs
- Déployer la solution auprès de tous les employés
- Assurer un support de proximité pendant la phase critique
- Effectuer les ajustements nécessaires
- Transférer vers le support régulier

### Étapes et responsabilités

#### Semaine 5, Jour 1-3 : Déploiement général
- **M'Bene (Support Client) & Client**
  - Activer les comptes de tous les employés
  - Envoyer les emails d'invitation avec les instructions
  - Organiser des sessions de formation pour les employés
  - Mettre en place un support sur site si nécessaire

#### Semaine 5, Jour 4-5 : Support intensif
- **M'Bene (Support Client) & Jérémie (CEO/CTO)**
  - Assurer un support réactif pour les premiers jours d'utilisation
  - Résoudre rapidement les problèmes rencontrés
  - Ajuster les configurations si nécessaire
  - Collecter les premiers retours d'utilisation

#### Semaine 6, Jour 1-3 : Ajustements et optimisation
- **M'Bene (Support Client) & Fidel (Business Dev)**
  - Analyser les données d'utilisation
  - Effectuer les ajustements de configuration nécessaires
  - Optimiser les processus en fonction des retours
  - Former les utilisateurs aux bonnes pratiques

#### Semaine 6, Jour 4-5 : Bilan et transition
- **Fidel (Business Dev) & Roxane (COO)**
  - Organiser une réunion de bilan avec le client
  - Présenter les statistiques d'adoption
  - Recueillir la satisfaction client
  - Transférer le client vers le support régulier
  - Planifier les points de suivi réguliers

### Livrables
- Solution déployée à l'ensemble des employés
- Rapport d'adoption et d'utilisation
- Document de bilan d'implémentation
- Plan de support continu
- Calendrier des points de suivi

## SUIVI POST-ONBOARDING

### Objectifs
- Assurer l'adoption continue de la solution
- Identifier les opportunités d'amélioration
- Fidéliser le client

### Actions récurrentes
- **M'Bene (Support Client)**
  - Point de suivi hebdomadaire pendant le premier mois
  - Point de suivi mensuel pendant les 3 premiers mois
  - Rapport mensuel d'utilisation et de performance

- **Fidel (Business Dev)**
  - Revue trimestrielle de satisfaction
  - Présentation des nouvelles fonctionnalités
  - Identification des opportunités d'upsell

### Annexe 3 : Spécificités par type de client

#### Grandes entreprises (>500 employés)
- Prévoir une phase d'analyse plus approfondie
- Envisager un déploiement par département
- Mettre en place un comité de pilotage
- Former des super-utilisateurs internes

#### PME (50-500 employés)
- Processus standard
- Formation groupée des managers
- Support à distance suffisant

#### TPE (<50 employés)
- Processus accéléré (3-4 semaines)
- Configuration simplifiée
- Formation combinée administrateurs/managers

#### Institutions publiques
- Prévoir des délais administratifs plus longs
- Adapter les formations au contexte public
- Intégrer les spécificités statutaires
- Prévoir une documentation plus détaillée

### Annexe 4 : Spécificités par méthode de pointage

#### Biométrie
- Prévoir le déploiement des dispositifs matériels
- Former à l'enregistrement des données biométriques
- Vérifier la conformité RGPD/lois locales
- Prévoir des méthodes alternatives en cas d'échec

#### QR Code
- Configurer la génération des QR codes
- Installer les dispositifs de scan aux points d'entrée
- Former à l'utilisation de l'application mobile
- Tester la robustesse du système en conditions réelles

#### Géolocalisation
- Configurer les périmètres géographiques
- Vérifier la précision GPS sur les sites
- Former à l'utilisation en cas de signal faible
- Configurer les alertes de sortie de zone

#### Badge NFC
- Programmer les badges
- Installer les lecteurs
- Configurer le système de détection
- Prévoir la gestion des badges perdus
